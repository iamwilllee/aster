# 运营后台与账号访问管理

管理员入口为 `/app/admin`，中文为 `/zh/app/admin`。依赖现有 auth/database；不单独启用收费服务、不要求 R2，也不会自动授予第一个注册者权限。`admin_user` 是服务端角色来源；已验证且未停用的管理员才能访问。

## 本地起步与 Agent 用法

先运行 `pnpm setup`，在本产品注册、验证邮箱并登录，再显式设置本地权限：

```bash
pnpm admin:grant operator@example.test
# 先授予另一位有效管理员，再撤销原角色
pnpm admin:revoke operator@example.test
```

命令读取当前根目录的 DB 名称，只操作本地 D1，拒绝 remote:true。授予对象必须已存在、已验证、未停用；撤销不能移除最后一位有效管理员。刷新工作台后显示入口。云端管理员按产品运维流程显式设置，以上命令不会设置云端角色；不提供公开申请、网页改角色或代理登录。

```text
$aster-new 为当前产品接入运营后台，保留品牌、页面、数据、登录和支付义务。
使用已有管理员角色，补用户查询、停用恢复和操作记录，先本地验收，暂不部署。
```

Agent 应先检查现有实现与迁移，按实际差异增量合并；授权内执行配置及验收，不能只列清单。已有产品不会因更新 Skill 自动获得后台；遵循 UPGRADING.md，保留原业务并重置受影响验收。

## 已实现的流程

- 按称呼/邮箱搜索、按访问状态筛选，每页 20 条。详情仅展示安全的资料、登录方式、项目/图片/有效会话数量和是否存在账务关联，不展示私人内容、密码、令牌或账单原始负载。
- 停用需要确认及固定原因：安全、滥用、支持或维护。状态、版本、会话撤销、操作记录在同一个 D1 batch 中提交，失败整体回滚。过期版本与重复操作返回冲突，刷新后重试。
- 停用撤销已有会话，并拒绝新的邮箱/Google 会话及私人接口。数据库触发器同时拦截停用账号的会话、账号凭据和用户更新，覆盖登录、旧重置链接等并发路径。已发出的响应和浏览器已有副本无法收回。
- 恢复保留原数据与凭据，需要重新登录，已撤销的会话不会恢复。不重建账号、不删除业务数据、不退订、不取消支付，也不撤下共享网站文章或封面。
- 不允许修改自己的访问状态，不允许停用最后一位有效管理员。最后管理员注销在私人图片清理前阻止，最终删除事务再次检查；角色 CLI 使用相同有效管理员计数规则。有效指已验证、未停用且持有角色。

停用期间用户无法使用工作台、导出、注销或账单门户。运营方仍须处理既有账务与支持请求；签名支付 Webhook 按原规则继续对账。不要删除支付记录来绕过限制。需要用户自助时先完成风险审查并恢复访问。

## 操作记录与隐私

记录停用、恢复及角色授予/撤销：事件 ID、可为空的操作者/对象 ID、固定动作/原因、来源和时间。不保存邮箱快照、自由文本原因、密码、会话、验证链接、SQL 参数或提供商负载。页面显示关联账号当前称呼/邮箱；账号删除后关联置空，最小事件保留。个人导出说明记录保留规则，不导出其他人的记录。

Web 状态操作记录真实管理员；本地 CLI/特权 SQL 的角色变更由触发器记录为 database/maintenance，不能假称已知的人类操作者。数据库拥有者仍有维护权限，这不是不可篡改的合规审计。没有自动留存期清理；有进一步保留/合规要求时需单独制定。

认证 SDK 日志保留原级别，以固定分类与请求 ID 记录事件；不输出原始 SDK 消息及参数。仍需结合产品监控排查，不将敏感凭据写回日志。

## 数据库升级与验收

增量迁移 `0007_puzzling_the_hood.sql` 新增 account_access、admin_audit 及认证/角色触发器。先审查并应用迁移，再发布兼容代码；本地 `pnpm db:migrate`，远端遵循 DATABASE.md 显式指定环境、备份及检查。不编辑已应用 SQL；后续表重建需保留这些自定义触发器，Drizzle 快照不代表触发器完整性。

验收至少覆盖普通/匿名拒绝、筛选分页、详情不泄密、全部会话失效、停用后邮箱/Google 会话创建及旧重置链接受阻、恢复重新登录、数据保留、自己/最后管理员/并发冲突、记录失败回滚、账号注销保护和签名支付回调。新产品复测自己的管理员入口与现有业务；本地或隔离生产 Worker 测试不代表云端部署、真实 OAuth、邮件或支付已接通。
