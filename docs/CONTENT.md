# 轻量内容管理与公开素材

可选 `content` 模块提供文章、帮助、公告的草稿、管理员预览、发布和撤下。后台 `/app/content`；公开目录 `/content`，详情 `/content/:slug`；中文沿用 `/zh`。内容按自身语言发布，不会自动翻译。普通访客无需账号；后台与所有编辑/素材接口都由服务端核验当前管理员。

## 选择与起步

content 依赖 auth、database，新产品默认关闭。只写文字不需要 R2；上传封面时再选 files，复用现有 ASSETS_BUCKET 绑定。它仍是私有 bucket，不启用 r2.dev 或公开域名。私有图片与网站素材使用独立表、对象命名空间和接口，不互相列出或转换。

```text
$aster-new 为当前项目增加文章和帮助内容管理，保留已有页面与登录。
内容使用 Catalog 主题，先本地验收。需要封面时启用网站素材，暂不部署。
```

Agent 先检查现有实现及规则，使用 `project:modules` 预览和应用带依据的 content 选择；图片需求再选择 files。不要重新初始化已有产品。纯公开展示站若需要后台，需一起选择数据库及一种实际登录方式，访客仍可匿名阅读。新产品初始化计划可直接包含 content=required。源预览开启本模块，所有起步 profile 仍默认关闭。

首次本地运行 setup 后，以本产品的本地测试邮箱注册并验证，再显式授予管理员：

```bash
pnpm admin:grant editor@example.test
# 先保留另一位已验证、未停用的管理员，再撤销角色
pnpm admin:revoke editor@example.test
```

命令读取当前项目根 DB，拒绝 remote:true，只修改本地角色，不创建账号或云端权限。用户需已存在、已验证且未停用，刷新工作台后可见入口。不能撤销最后一位有效管理员；详见 [运营后台](ADMIN.md)。真实产品的管理员授权遵循该产品的运维流程，不为公众提供“申请管理员”或自动授予第一个注册用户。

## 编辑和发布

1. 在内容管理创建草稿，填写标题、英文小写网址标识、类型、内容语言、分类、摘要及正文。
2. 正文为纯文本，空行分段，最多 12,000 字符；HTML 作为文本显示。当前没有富文本、Markdown 执行、脚本或嵌入功能。
3. 在公开素材页上传 PNG/JPEG/WebP，再在草稿中选择封面。保存草稿不会发布，也不会改变已有线上版本。
4. 管理员可预览草稿。确认后通过“发布已保存草稿”发布，不包含未保存的编辑。标题、正文与选中封面将对访客公开。
5. 再次编辑只改变草稿，重新发布才替换公开快照。更改网址后旧网址返回 404，不自动重定向。
6. 撤下保留草稿，但公开详情不再提供；图片没有其他已发布引用时也停止公开读取。需要彻底删除时先撤下，再删草稿，最后按引用情况清理素材。

每条记录携带 revision，修改、发布、撤下和删除都要求当前版本；同时编辑的落后版本返回冲突，先刷新核对，再继续。一个站点最多 500 条内容，后台及公开列表均分页，每页 12 条。公开目录支持搜索标题/摘要、类型、分类；只查询已发布版本。重复的语言＋网址不能同时发布，公开版本和封面引用在同一条 D1 写入中更新。

SEO 标题和描述可单独填写，留空采用标题/摘要。详情为服务端渲染；公开 URL 使用当前语言及产品 origin。只有开启 PUBLIC_INDEXABLE 时才把公开目录/已发布路径加入 sitemap，草稿不加入；预发布保持 noindex。需要多语言内容时各自创建相应语言版本，不继承另一语言的正文。

## 网站素材的公开边界

网站素材属于站点，所有管理员可管理；上传时仍不可被访客读取。只有被已发布内容引用的 ready 素材，可通过 `/api/content/assets/:id` 匿名获取；管理预览使用独立鉴权接口。私人头像、项目封面和其他私有 file_asset ID 不能被用作公开内容封面。

复用既有 R2 绑定仅减少配置，不代表复用权限。对象 key 由服务器生成，不接受用户输入 URL 或 key，不返回内部对象路径。图片读取流式输出，使用 no-store / nosniff；公开入口每次核验当前发布引用。撤下控制后续请求，已下载、截图或之前已开始的传输无法收回。不要在网站素材上传保密文件，也不要在外部 CDN 设置覆盖这些响应头的缓存规则。

每站最多 100 份素材、合计 250 MiB，单张 5 MiB；pending/deleting 均占预留配额，原子检查并发写入。类型声明需匹配文件头；此版本不承诺完整图片解码、转码、病毒扫描或敏感信息清理，发布前由编辑核对实际文件。站点配额不是云账单封顶。

模糊上传失败保留 pending，通过对象大小、类型和标识核实成功后可恢复为 ready；不存在或未知对象不直接丢弃，交由站点运维调查。撤销了上传者权限时，另一位管理员可继续核对已知对象。删除前必须移除草稿和已发布快照的所有引用；删除失败保留 deleting 状态供重试。不因移除一个封面就自动删除可能复用的素材。

## 账号注销与保留

content_entry / content_asset 属于站点共同资产，创建/编辑/上传者仅作可空关联。个人 JSON 导出不包含网站正文或素材，siteData 字段说明其站点归属与保留边界。账号注销前若有关联，需明确确认保留网站内容；通过原身份与账务检查后，删除账号并将这些关联置空，不删除公共内容或站点素材。私人图片仍遵循原清理流程。

关闭 content 会关闭公开及管理入口，不删除记录、素材或共享保留责任。已有 required 内容模块退役需要审查公开链接、引用、其他管理员与用户影响；不要仅靠切换 profile 假装完成清理。关闭 files 也不代表历史网站素材已删除。新增编辑/媒体业务应继续维护引用、导出和生命周期映射。

## 迁移、升级与验收

新增迁移 `0006_lying_black_cat.sql` 必须先在目标环境按 DATABASE.md 审查、备份和应用，再发布兼容代码；不要修改旧迁移或上传本地测试库。已有产品按 UPGRADING.md 合并模块策略、完整鉴权/API/UI、词典、脚本和迁移，不能只复制页面。

本地验收至少覆盖管理员/普通账号/匿名访客、草稿隔离、预览、发布与替换、刷新持久化、撤下、公开封面恢复/删除、旧版本冲突、网址/语言、SEO、原样显示 HTML、手机/深浅主题及编辑者注销后的共享保留。上线要求当前产品 `content-live` 的真实目标环境记录（business/provider/real/passed）；使用图片时还需所选 files 的云端验收。deploy 校验记录，不能代替实际业务检查。

本地 D1/R2 测试不证明 Cloudflare 云端资源、套餐、真实登录或邮件已接通。按用户授权继续配置与真实验收，不额外开通付费或把清单当作已完成。

参考实现依据：[D1 prepared statements 与 batch](https://developers.cloudflare.com/d1/worker-api/d1-database/)、[R2 Workers API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)。
