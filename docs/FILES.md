# 私有图片资源库

图片模块用于当前登录用户的头像和项目封面，也可复用到其他私有业务。`files=true` 依赖 auth、database；新产品默认关闭，按流程选择后启用。Aster 源预览已开启，以便本地体验。入口 `/app/files`，所有内容接口都检查所属用户，不提供公开 bucket URL、匿名图片或跨用户共享。

## 本地使用

完成 `pnpm install --frozen-lockfile`、`pnpm setup` 后，运行 `pnpm dev`。注册并在本地收件箱验证后：

1. 在「图片资源库」上传 PNG、JPEG 或 WebP。
2. 刷新后确认图片仍存在，选择为设置页头像或项目封面。
3. 更换/移除引用后删除图片；仍被引用时禁止删除。

本地 R2 与 D1 都由 Wrangler 在 `.wrangler/state/` 模拟持久化，不需要云账户，不上传云端。setup 保留已有数据。不要把本地测试数据库或对象目录上传生产。

每用户最多 20 张、合计 50 MiB，单张 5 MiB，pending/deleting 同样占用配额。配额在同一 D1 写入中预留，并发上传不能越过检查；这是应用配额，不是 Cloudflare 账单封顶。类型按声明 MIME 和文件头共同检查，拒绝 SVG、其他文件类型与无效名称。此版本不提供完整解码校验、转码、压缩、缩略图生成、恶意内容扫描、断点上传或通用附件库。

## 数据与失败恢复

`file_asset` 保存所有者、不可变对象 key、文件名、类型、字节数及 pending/ready/deleting 状态。内部 key 不进入客户端或 JSON 导出。对象名由服务端生成，不使用原文件名或用户可控路径；内容从 `/api/files/:id/content` 以所属用户身份流式读取，响应使用 private/no-store 和 nosniff。

上传先原子预留 pending，再写对象，成功后变 ready。模糊写入失败会保留 pending，提示用户不要重复上传；「检查上传」用对象元数据核实已完成写入。没有对象或无法证明成功时保持待核对，不能把一次未找到当成永不会到达的写入。此时由站点支持调查原请求与存储状态；没有自动丢弃预留或后台清扫器。

删除先确认没有头像/项目封面引用并标为 deleting，再删对象、移除元数据。失败保留记录和配额，可以重试。设置引用及创建/修改封面都在服务端核验 owner + ready；业务表的外键不代替所有权检查。新增其他引用字段时必须同步引用计数、引用写入保护、导出与注销清理，不能仅存一条 URL。

## 账号导出与注销

JSON 导出包含所属图片的元数据，不包含图片字节。注销前保存需要的原图。注销在现有账号租约与身份/账务复核下清理私有对象，确认清理后才删除账号；即使 files 后来关闭，历史对象仍需清理。未确认上传会阻止注销。

R2 和 D1 不在同一事务中。清理失败可能已有部分图片被删除，但账号与剩余记录会保留供重试；不能承诺失败时所有图片都原样保留。资源表对 user 使用限制删除，最终注销检查没有残留对象记录；不能直接绕过原注销接口删除 user。详情见 [账号生命周期](ACCOUNT-LIFECYCLE.md)。

## 云端接入与验收

通过 `project:modules --input ...` 先预览再应用带依据的 files 选择；新选模块只准备 `ASSETS_BUCKET` 占位 binding。已有产品先按 [升级指南](UPGRADING.md) 审查代码与 additive migration `0005_vengeful_captain_stacy.sql`，不要编辑已应用迁移。关闭模块会关闭 `/app/files` 和 `/api/files`，但不删除 bucket、数据或历史清理责任；required 文件能力不能通过普通组合切换草率退役。

在用户授权的配置/部署范围内，由 Agent 核对 R2 开通条件、费用、当前账户权限，分别配置 staging/production 的独立私有 bucket，再按数据库发布流程应用迁移、发布兼容代码。不要启用公网 bucket、自定义公开域名或 `remote:true` 本地 binding 来绕开隔离。R2 的开通、绑定支付方式与按量费用须看当前账户，不能承诺无需绑定支付方式；详见 [成本策略](COSTS.md)。本地开发始终可先完成。

正式发布要求当前产品 `files-live` 用例（kind=business、scope=provider、verification=real、status=passed），证据至少覆盖目标环境真实上传、刷新读取、另一账号拒绝访问、引用保护、删除及注销清理；代码/本地 Miniflare 测试不算云端验收。deploy 检查 bucket 名称、环境隔离和验收记录，但不会创建资源或证明业务正确。只有选中的能力参与发布门槛。

## 与网站素材分开

content 模块的公开封面另用 content_asset 表与 content/ 对象命名空间，详见 [内容管理](CONTENT.md)。复用 ASSETS_BUCKET 不复用公开权限；这里的个人 file_asset 仍只允许所属用户访问，不能用其 ID 作为公开封面。站点素材在上传者注销后保留，个人图片仍需清理。
