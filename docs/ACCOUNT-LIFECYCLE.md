# 数据导出与账号注销

属于既有 auth 能力，入口在 `/app/settings`（中文 `/zh/app/settings`）末尾。无需新增付费服务或依赖；采用本版注销的所有 auth 产品（包括未选支付的产品）都需要新增的 `0003_nervous_mauler.sql` 与 `0004_married_boom_boom.sql` 迁移。auth 关闭时页面和全部私有接口一起关闭。

## 用户流程

**导出**：点击“下载 JSON”获得 `account-data.json`。包含个人资料、自己的项目，以及非敏感订阅/结账状态。导出不进入查询缓存、服务器文件、公共对象存储或日志。文件含个人信息，由用户自行保管。

**注销**：先按需导出，再打开确认弹窗。密码账号输入当前密码；所有账号必须输入大写 `DELETE`。取消不会修改数据。成功后退出全部设备、清除当前认证 Cookie 和浏览器查询缓存，整页导航到登录页。以后用同一邮箱重新注册会得到全新的账号和空工作区。

Google-only 账号不添加密码或邮件要求：退出并通过原 Google 方式重新登录，五分钟内回设置页确认。时限取自数据库 session.created_at，刷新页面或会话续期不会重置。此处验证的是近期应用登录，不承诺 Google 一定再次要求输入密码或 MFA。未知登录方式关闭自助注销，需先设计对应重新验证方式。

## 支付账号注销

普通无支付历史账号仍直接验证身份、确认注销。有支付历史时先点击“核对支付状态”，按结果处理；最终注销提交会再次核对，之前的 ready 响应不是许可凭据。

| 核对结果                                                            | 后续操作                                                 |
| ------------------------------------------------------------------- | -------------------------------------------------------- |
| 有效、试用或其他未结束订阅                                          | 到账单门户管理；关闭续费后等待实际结束，再核对           |
| 未完成结账链接                                                      | 完成支付，或明确确认“关闭未完成结账”使本产品所属链接失效 |
| draft/open/uncollectible 等未解决账单                               | 通过账单服务或站点支持处理，再核对                       |
| 订阅已 canceled/incomplete_expired、结账已结束、账单均 paid/void    | 允许进入注销确认                                         |
| 平台不可用、身份不匹配、列表不完整、未知 pending 预留或超出处理上限 | 保持拦截，可重试或联系站点支持                           |

核对使用当前测试密钥读取 Stripe 的本地已知结账及订阅，同时按关联客户列出订阅、结账和账单，防止漏掉尚未收到的回调。未知的开放结账链接不会被擅自关闭。active 且 cancel_at_period_end=true 仍然阻止注销；不会因为本地“canceled”、隐藏 billing 或关闭 BILLING_ENABLED 就直接放行。已关闭的新结账不影响门户和 Webhook。

Creem 核对与 Stripe 结果汇总，不能仅核对当前新结账渠道。Creem 重新读取已知结账/订阅、有界扫描商店订阅及关联客户交易；未结束订阅、开放结账、未解决交易、列表截断或身份不符均阻止注销。没有已核实的 expire API 时不提供自动关闭按钮，需在平台处理或等待实际失效后重新核对。

“关闭未完成结账”有单独确认弹窗，仅调用当前用户已核实的 open Checkout Session 的 expire，不取消订阅、退款、撤销账单或操作 Stripe Customer。支付在关闭操作期间完成时重新核对，不能按此前 open 状态继续注销。部分链接已经关闭后又发生平台错误时，返回未知状态；再次核对实际状态，不声称可以回滚外部操作。

供应商核对有界：最多各 100 条本地订阅/结账、5 个客户、每类列表最多 3 页（每页 100），请求间使用 25 秒调度预算，单请求超时 5 秒且不自动重试；最后一次调用可能持续到其超时边界。超限/截断不当作通过；大规模产品需要独立审核或异步流程。客户共用给其他产品时，其他未结束订阅/开放链接或未解决账单也可能保守阻止注销，需要按实际客户隔离规则处理。

创建结账前以用户仍存在、没有注销核对锁为条件写入 pending 预留，再调用供应商。失败/超时后保留不透明 pending 记录：没有返回 Session ID 时不能通过“等待足够久”推断外部交易不存在；仍需授权的人工/专用对账流程，不能直接删预留来解锁注销。

## 归档、并发与保留边界

新增三张表：`billing_account_state` 保存核对租约/已注销标记，`billing_subscription_archive` 与 `billing_checkout_archive` 保存注销后的最小账务关联。0004 为订阅、结账和两张归档表增加 provider，旧记录默认 stripe；Creem ID 另有 creem: 命名空间。迁移仅增加表/索引/字段，不改旧迁移、不回填真实账号或上传本地库。

核对与注销持有每账号最多 90 秒的 D1 条件写租约。新的结账暂时拒绝，Webhook 返回可重试失败；已开始的结账有 pending 预留而不能漏过。锁不可被其他请求覆盖，过期后可重新核对；旧请求不能释放新请求的锁。最终事务用数据库时钟、当前会话、凭据版本/Google 登录时限和租约确认授权，随后在同一 batch 中封存注销状态、复制账务记录、清理私有数据、删除 user 并释放锁。任何 SQL 失败都会回滚归档和删除；不会先删账号再尽力补账。锁只协调当前 D1/代码路径，不是 Stripe 与数据库之间的分布式事务。

归档不保存姓名、邮箱、头像、密码、会话或 OAuth token。保留原不透明用户 ID（owner_ref）、客户/订阅/价格/结账 ID、必要状态与修订/时间，用于归属验证、事件幂等和后续对账。这是可由供应商记录关联的去标识化数据，**不是不可逆的匿名数据**；Stripe 自己保存的客户/账单也不会随本地注销自动删除。实际产品需在隐私说明中定义保留目的、期限、访问和清理机制，不能将本底座当成法律合规结论。

正常账务行随 user 外键级联移除，归档无 user 外键而保留。已签名的晚到 Webhook 仍重新读取供应商状态，校验已归档客户与原用户关联，并按修订号更新归档、去重事件；不会重新创建用户、登录凭据或权益。与已知归档客户不匹配的事件仍拒绝并需处理。注销后出现非结束订阅状态会记录 `closed_account_billing_attention` 运维事件；具体产品必须接入告警/人工处理，不能因本地已注销就忽略外部账务。

同一邮箱重新注册得到不同 ID，不继承归档记录或旧权益。全局 billing_event 保留。当前支持 Stripe / Creem TEST ONLY，渠道接入与切换见 [支付指南](PAYMENTS.md)；真实收费、自动取消订阅/退款、供应商客户删除和完整账务保留管理仍需独立实施与验收。

## 接口与数据归属

| 接口                                | 行为                                                                       |
| ----------------------------------- | -------------------------------------------------------------------------- |
| `GET /api/account/lifecycle`        | 返回验证方式、近期登录状态、账务阻塞状态，不返回密码/令牌/账务标识         |
| `POST /api/account/export`          | 当前账号的 JSON 附件；不接受目标 userId                                    |
| `POST /api/account/billing-review`  | 重新核对供应商并同步当前账务状态，不自动关闭链接                           |
| `POST /api/account/close-checkouts` | 严格接收 confirmation=CLOSE，关闭核实过的未完成结账链接                    |
| `POST /api/account/delete`          | 严格接收 confirmation 和可选 currentPassword；不接收 userId 或跳过检查参数 |

导出是明确白名单：profile 的 name/email/image/createdAt；project 的 id/name/description/status/createdAt/updatedAt；订阅的 provider/status/currentPeriodEnd/cancelAtPeriodEnd；结账的 provider/status/createdAt。不导出密码散列、认证账号、OAuth access/refresh/id token、session、验证记录、原始 IP/UA、管理员名单、Stripe customer/subscription/price ID 或全库 SQL。

导出在一个 D1 batch 中取得当前账号的快照，复查当前会话。每类集合最多即时导出 1000 条，JSON 最多 2,000,000 字节；超限明确拒绝，绝不交付悄悄截断的“完整”副本。大规模产品应另行实现有界流式/异步导出与私有下载，不用公开 R2 链接绕过授权。即使 projects/billing 已关闭，历史所属数据仍纳入导出和账务保护。

满足注销条件时，先在事务中归档已有账务，再实际删除 user，由现有外键原子级联删除 session、account、project 和 admin_user；同一 batch 清理 value 为准确 user ID 的 reset-password 验证记录，以及该邮箱的本地 dev_mail。其他用户和全局 billing_event 不变。SDK 邮箱验证 JWT 原先只绑定邮箱，现在发出的链接额外签名 sub=user.id，验证钩子校验具体账号，避免旧链接验证重新注册的账号。**升级前发出的不带 sub 的未验证链接需要重发**，不能通过放宽校验继续沿用。

写请求复用精确 Origin、请求大小、权威会话与原子限流。导出、支付核对和关闭结账各每用户每分钟 3 次，注销 5 次，并计入普通私有写入的 30 次限制。注销 SQL 再检查当前会话、密码凭据版本或 Google 近期登录，以及有效的核对租约；不会只依靠此前页面检查。原生 `/api/auth/delete-user`、`delete-user/callback` 和 `verify-password` HTTP 入口关闭，防止绕过私有流程。密码验证复用 Better Auth 内部 API。

## Agent 增量接入

在实际产品读取 PROJECT.md、schema、现有业务归属与支付状态，按 [升级指南](UPGRADING.md) 审阅采用。合并 lifecycle/verification 模块、API 分发、原生路径关闭、限流、设置页与登录成功提示、双语词典及测试；支付产品同时合并结账预留/核对/归档回调与新增迁移。不能只升级 Skill 或只复制弹窗。先应用新增迁移，再部署兼容代码；旧 Worker 可在新增表存在时继续服务，但不理解已注销账号的归档回调。因此上线此流程后回滚不能只切回旧代码：需要兼容处理归档的版本或暂停相关操作并安排回调重放，不要覆盖恢复数据库来丢弃注销后账务。

此底座只知道示例 project 的归属。新增文章、文件、团队或其他业务时，必须明确个人所有、共享、应转移与应保留的数据，更新导出白名单和注销清理，并验证外键/事务行为。团队或外部文件未处理前，不宣称“删除全部业务数据”。不要删除其他成员、公共内容或数据库备份；备份保留/恢复后的再删除由实际产品另定。

重置受影响认证/业务验收，在本产品执行检查。至少验证：跨账号隔离、无秘密导出、真实下载、超限不截断、错误密码/取消不改变数据、重复注销拒绝、全部旧会话失效、同邮箱新账号为空、旧验证/找回链接不可复活、支付状态重新核对、未解决账单拦截、结账关闭竞态、归档原子性、晚到/重复回调、并发结账拦截、Google-only 新旧会话、auth-off、移动端/明暗/语言/错误恢复。Google-only 的本地 D1 或 UI fixture 不证明真实 OAuth 重新登录成功。

执行 `pnpm check`、`pnpm format:check`、`pnpm test:e2e` 和三个 profile 的 `pnpm test:production`。真实产品上线仍需其自己的所选邮件/Google 供应商验收；源码本地结果不继承为云端证据。

实现核对项目锁定的 Better Auth 1.7.12；参考 [用户与账号](https://better-auth.com/docs/concepts/users-accounts) 和 [D1 batch 事务](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)。依赖升级时重新检查内部 API、JWT 钩子、Cookie 与删除行为。

核对依据：[Stripe 订阅列表](https://docs.stripe.com/api/subscriptions/list)、[读取结账](https://docs.stripe.com/api/checkout/sessions/retrieve)、[关闭结账](https://docs.stripe.com/api/checkout/sessions/expire)。供应商 HTTP 夹具和签名事件测试均为本地证据，不能标记为真实 Stripe 沙箱验收。

## 私有图片

图片元数据纳入所属用户 JSON 导出，不含原文件或内部对象 key。注销前须自行保存原图。注销在现有账号租约下先执行图片清理，再进行最终 D1 删除；pending 上传阻止注销。存储失败保留账号与未完成记录供重试，但 R2/D1 不同事务，可能已删除部分图片。即使文件模块关闭也检查历史记录；新增业务引用时同步清理映射和引用检查。参见 [图片指南](FILES.md)。

## 网站共享内容

content_entry 与 content_asset 是站点资产，个人导出仅附 siteData 归属说明，不包含站点正文/素材。有关联的账号注销需 retainSiteContent=true 明确确认保留；在账号租约下核对，编辑写入同样受此租约保护。通过原有身份和账务核对后，FK 将 created_by/updated_by/uploaded_by 置空，保留正文、发布快照和素材。禁止把它们当私人图片清理。角色可被撤销的贡献者仍需知道保留边界；另一位管理员负责站点后续管理。新增共享业务继续单独定义保留规则。

## 管理员与最小操作记录

最后一位已验证、未停用的管理员需先指定另一位有效管理员才能注销。服务端在私人图片清理前检查，并在最终数据库删除事务中再次检查；清理期间角色并发变化仍可能使最终删除受阻，此时部分图片可能已经清理，应按当前状态续做，不声称全部回滚。停用账号不能自助导出或注销，需要运营支持先处理状态和账务。

管理员角色/访问状态的最小操作记录在注销后保留，操作者及对象 FK 置空，不保存邮箱快照或自由文本。个人 JSON 导出说明保留规则，不包含跨账号审计事件。共享内容贡献者的保留确认、账务档案和晚到回调规则仍生效。见 [ADMIN.md](ADMIN.md)。
