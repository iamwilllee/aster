# 0.3 开发线

基线为已提交的 0.2.0-beta.1 无支付候选；当前是 next/0.3 / 0.3.0-dev.0，尚未发布。0.2 继续在 main 收尾和修复，普通 Skill 保持指向稳定源，0.3 的目录不能悄悄替换用户安装的 Skill。

## 已有支付实现

Stripe 与 Creem TEST 订阅适配已包含结账、账单门户、原始体签名验证、事件去重、提供商当前状态核对、D1 修订号对账与权益同步。已有渠道切换保留历史账务，账户注销前检查未结订阅/结账并保留最小归档与晚到回调处理。相关单元/D1/界面夹具已存在。

这些代码是继续开发的基础，不代表真实商户沙箱、正式收款、一次性购买、退款/争议自动化或完整订单账本已经完成。默认仍为 billing=false；不在准备分支时切换正式密钥、添加真实支付绑定或开通服务。

## 下一阶段

- 按当前产品的需求和渠道条件确定 0.3 支付范围，先完成真实测试环境的结账、回调、取消/失败、门户与跨账号验收。
- 在明确授权下开发正式模式，并保持渠道隔离、签名校验、幂等、权益回收和账务兼容性；不只换密钥或信任结账成功回跳。
- 按需决定一次性购买、订单、退款等后续范围，不为首轮默认堆入全部交易类型。
- 确保无支付用户升级后仍不必配置支付；0.2 的公共修复用小提交同步并分别回归。

## 并行开发约定

每条线使用独立 worktree、node_modules、本地 .dev.vars 与 .wrangler 数据。0.3 可使用 localhost:3102，0.2 保持 127.0.0.1:3100，避免 Cookie 相互覆盖。开发 E2E 跟随当前回环 APP_ORIGIN，不能误用另一条线的服务器。隔离生产验收目前固定 3110，应串行运行，端口占用时不终止已有服务。

0.3 达到验收条件后再审阅合并 main、运行该提交的 CI 和发布；如届时需要长期维护 0.2，再从对应提交建立 release/0.2。目录隔离不能避免 Git 合并冲突，文件/迁移/品牌/账务仍须按差异处理。
