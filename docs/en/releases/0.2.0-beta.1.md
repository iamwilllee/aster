# v0.2.0-beta.1 — Non-payment public preview

[中文](../../releases/0.2.0-beta.1.md)

The first public prerelease focused on non-payment products. Publication/download status is authoritative in [GitHub Releases](https://github.com/iamwilllee/aster/releases).

## Supported scope

- showcase: bilingual public pages/themes/SEO without database/accounts/mail/payments.
- web-app: D1/email-password verification/recovery/sessions/profile/private projects/export/deletion/explicitly granted administration. Google/billing/images/content/AI default off.
- Skill, initialization/recovery, capability-aware checks and selected upgrade scans/backed-up merges/adoption/conservative rollback.
- Public copy review removes development banners/test placeholders/unused sample promotion while retaining actual availability/excerpts/private previews.
- Finite staggered marketing entrances/one-time reveals/subtle hover with theme timing and reduced-motion/keyboard/no-script fallbacks.
- Sage/Catalog light/dark, shared controls/blueprints, real system fonts or actually loaded brand fonts, separate reading/tool typography.

Source previews enable optional image/content samples; text needs no R2. Configure/accept actual image/Google services per product. Available code/local behavior is not default activation of cloud services.

## Fixes and boundaries

- Unexpected auth SDK failures reach the sanitized application boundary without raw SQL parameters, preserving expected status/cookies/limits and structured severity/request IDs.
- Production checks follow selected capabilities: verify closed disabled billing APIs and ordinary app locale/navigation/sessions without payment keys.
- Stripe/Creem remain experimental TEST, not live collection. AI/usage ledger are not implemented. Mail/OAuth/R2/cloud deployment need product-specific setup/acceptance; no permanent zero-cost guarantee.

## Use and adoption

Start with --profile showcase/web-app or an Agent-generated plan. No npm initializer has been published; use locked source and bundled CLI/Skill.

Existing products follow [Upgrading](../UPGRADING.md), preserving brand/business/secrets/database/billing. Merge complete auth.server.ts/http.server.ts/logging/entry dependencies and verify actual errors/login/reset/sessions, not just the logger. Review/apply additive SQL first; never overwrite applied history. Partial adoption is not a whole-version upgrade.

```bash
git clone --branch v0.2.0-beta.1 --depth 1 https://github.com/iamwilllee/aster.git
cd aster
pnpm install --frozen-lockfile
pnpm setup
pnpm skill:install
```

The installed Skill uses its local source; the installer preserves links pointing elsewhere. Source updates do not update products automatically. Invoke $aster-new in the target to inspect/adopt/regress independently. Deployment/mail/OAuth/storage still require actual product scope.

The release distributes source/Skill, not product cloud operations or merchant/provider/live-payment approval. Maintainers follow [Releasing](../RELEASING.md) to align exact commit CI/public files/tag/Release.
