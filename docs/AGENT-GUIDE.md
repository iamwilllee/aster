# 把 Aster 交给 Agent 使用

适用版本：v0.2.0-beta.1 发布候选；首版默认无支付。推荐入口是 `$aster-new` Skill 或 `pnpm aster:new`，手动复制和长提示词保留为备用方式。直接在已打开的项目里提供产品需求即可；默认使用当前目录，也接受你指定的新路径。

先按 [能力选择](MODULES.md) 判断产品是否需要账号、数据、邮件或支付。公开展示站可使用 showcase；普通数据应用用 web-app；AI 仅在需求明确时另行开发接入。

需要收款时先读 [支付主体与供应商选型](PAYMENTS.md)。个人、个体工商户和公司均是目标用户；按当前产品的地区、主体和结算条件选择渠道。现阶段有 Stripe / Creem 测试适配，按产品的 payment-provider 决策配置 BILLING_PROVIDER，保留旧渠道账务与密钥。其他渠道保持待开发；代码和模拟测试不能当成真实商户验收。

页面与内容开发先读 [页面蓝图](PAGE-BLUEPRINTS.md)：按用户任务规划逐页内容，再选择官网、目录阅读、数据工作台或组合；本地样例 `/dev/blueprints` 可直接体验。保留已有品牌，按需采用，真实产品不继承虚构内容和内存保存语义。

字体与阅读效果按 [前端约定](FRONTEND.md#字体与阅读清晰度)。模板默认使用可用的系统字体，品牌字体必须实际加载并检查真实渲染；官网段落与紧凑工具采用不同字号层级，不能用全局加粗或文字缩放代替排版。既有产品需增量采用并独立验收。

## 推荐：一句需求开始

在底座源目录先执行一次 `pnpm install --frozen-lockfile`，然后安装 Skill：

```bash
pnpm skill:install
```

安装器把 `skills/aster-new` 链接到 `~/.agents/skills/aster-new`；已有同名 Skill 指向别处时会退出，不覆盖。该用户目录与软链接发现方式参见 [OpenAI 官方 Skill 文档](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills)。保留底座源目录；若移动了它，需要检查旧链接并重新安装。

在新 Agent 会话中调用：

```text
$aster-new 在当前项目做一个私人代码片段库：
注册登录后能新建、搜索、编辑、删除自己的片段，中英文和手机可用。
做完本地首版，暂不部署。
```

Skill 先判断当前目录：没有目录就创建，空目录或只有 Git/说明/编辑器配置就原地初始化，已有 Aster 读取原进度继续，其他应用先检查再增量接入。已有内容不被整份模板覆盖。用户指定路径时按当前工作目录解析。随后记录需求并按要求开发、验收，无需为了初始化再切换一次任务。若 Skill 选择器尚未出现，先新开会话；仍不可见时直接让 Agent 读取 `skills/aster-new/SKILL.md`。其他支持 Skill 的 Agent 按自身的发现方式安装；不支持时使用 CLI。底座源码位于 [iamwilllee/aster](https://github.com/iamwilllee/aster)，先克隆再运行仓库命令；当前没有已发布的 npm 包，不要使用虚构的 `npx create-...` 或 `/aster-new` 内置命令。

## 推荐：一个终端命令初始化

从底座源目录执行：

```bash
pnpm aster:new ../snippet-shelf --name "Snippet Shelf" --brief "私人代码片段库"
```

| 参数             | 作用                                                          |
| ---------------- | ------------------------------------------------------------- |
| 目标目录（可选） | 默认当前工作目录；支持未创建/空/项目元数据目录，底座源受保护  |
| `--name`         | 产品展示名；默认取目录名，package/Worker 名由目录生成         |
| `--brief`        | 写入 `PROJECT.md` 的首个需求；不填则保留待填写模板            |
| `--plan`         | Agent 整理的计划 JSON；记录目标、模块选择依据、任务和验收步骤 |
| `--no-install`   | 只初始化文件，不安装依赖或迁移 D1                             |
| `--inspect`      | 只读判断目录状态，不初始化或修改已有文件                      |
| `--help`         | 查看命令说明                                                  |

命令默认完成干净复制、包名/展示名/Worker 名初始化、新产品 README 和 `PROJECT.md`、随机本地密钥、冻结依赖安装、`pnpm setup` 和生成文件格式化。保留许可、锁文件和底座来源版本；不继承原云 ID、域名路由、提供商密钥、`.npmrc` 凭据、开发库或私有产物。默认不配置 R2/EMAIL binding，云端功能保持关闭。源码业务逻辑和迁移仍然保留，实际产品需要 Agent 实现。

已打开项目目录时可直接让 Skill 原地处理；初始化后仍在该项目继续。已有 Git 保留，已有 README 不改写而新增 ASTER.md；AGENTS 和 .gitignore 保留原内容并追加底座段落，编辑器配置不动。已有应用的 CLI 路径只检查，由 Agent 按原架构增量开发。

初始化后在目标目录运行 `pnpm dev`。不会自动启动服务、切换当前聊天的项目目录、创建 Git 历史或部署。生成产品不再提供底座初始化命令，应回到原始底座创建下一个产品，避免把已有产品误当成模板。

如果安装/迁移失败，目标文件和步骤状态会保留；到该目录修复环境，再运行 `pnpm project:resume`。`--no-install` 后也用此命令继续。不要重新复制、重置密钥或覆盖已有业务。完整基础检查使用 `pnpm check`、`pnpm format:check`；用户流程和运行时验收见下文。

本地 D1 仍使用 `starter-db` 这个配置内名称，由每个产品自己的 `.wrangler` 隔离。真实云端 D1 需独立创建并配置；不要根据相同示例名认定它们共享数据库。CLI 仅初始化，不会把自然语言需求自动变成业务功能；Skill 才会让 Agent 继续开发。

数据库发布采用 [指定环境的计划、备份、迁移和恢复流程](DATABASE.md)。`db:migrate` 读取本产品根 DB 名，仅操作本地；远端使用 `project:database plan/check/apply/status`，显式选择 staging 或 production。Agent 在已授权范围内执行，变更 SQL/目标后重新计划，中断先核对当前远端状态再续做；不上传开发库，不自动覆盖恢复。实际 deploy 遇到远端漏迁移或完整性错误会停止，deploy:check 仍只查本地。

## 需求、检查、交接与业务验收

Skill 会根据当前需求和上下文填写 `starter.project.json`，保留选择理由和依据（用户明确要求 / 上下文推断 / 默认值），并将目标、用户和核心流程摘要填入 `PROJECT.md`。脚本不靠关键词启用模块；没有经过 Agent 整理的需求会保留待定状态。关键未定事项记录为阻塞决策，其他部分可以先开发。

```bash
pnpm project:doctor          # 只读环境/配置/端口检查，不显示秘密或停止服务
pnpm project:status          # 查看初始化、任务、用例和下一步
pnpm project:resume          # 恢复固定的本地安装/setup，不重建项目
pnpm project:check           # 校验计划、选择关系和证据路径
pnpm project:check --ready   # 要求必需业务用例全部通过；未完成时退出码 2
```

环境检查即使在依赖缺失时也能运行；只检查本地状态和配置形状，不查询远端密钥或宣称供应商可用。被占用的端口是待识别的现有服务，不会被自动结束。恢复入口也不依赖已安装的包；它按需要安装冻结依赖，幂等执行本地 setup，保留原业务代码、密钥和验收记录。配置/密钥缺失时要求先恢复本产品配置，不自动换密钥。

`PROJECT.md` 保存人类说明，机器计划保存任务与验收状态；运行时配置仍在原有配置文件中。机器计划由脚本使用稳定 JSON 格式写入，已从 Prettier 中排除。字段和完整示例见 [Skill 流程参考](../skills/aster-new/references/workflow.md)。旧的手工复制项目没有机器计划时，可继续原开发方式；恢复命令不会猜测或覆盖它，完整新流程请从初始化器创建。

任务 implemented 需要源文件证据；用例 passed 需要本产品实际报告/截图文件。脚本检查路径存在、记录一致和 local/mock/real 的区分；**不会自动证明图片内容或业务正确**。Agent 需要真正运行流程、查看结果，再更新记录。模拟测试不能通过 scope=provider 的真实供应商用例，底座历史 QA 不能作为本产品证据。初始化和基础测试通过不等于业务完成，更不等于已上线。

默认保留一项待执行的基础检查；Agent 还要生成本产品的业务用例，包括成功、无效输入、错误/空态、持久化、跨用户边界及手机/语言场景。需求或实现变化后，应重置受影响用例，清理失效证据；已解决的阻塞在确认后清理。

## 未使用 Skill 时交给 Agent 的任务

未使用 Skill 时，在初始化器生成的新目录中填写 `PROJECT.md` 和 `starter.project.json`；[产品需求模板](templates/PROJECT-BRIEF.md) 可作参考，不覆盖已有交接。没确定的项目写“待定”，Agent 可以先完成不依赖这些信息的部分。

下面这段用于已初始化项目；只有想放到别处时才额外给出路径。新建空项目也可以直接调用 Skill，由它识别当前目录。

```text
请基于当前 Aster 开发这个产品。先读取 AGENTS.md、README.md、
docs/AGENT-GUIDE.md、docs/DEVELOPMENT.md 和 PROJECT.md，再检查现有实现。

以 PROJECT.md 为需求来源，复用 TanStack Start + Cloudflare Workers/D1、
Better Auth、Drizzle 和现有 shadcn/Base UI 组件。先说明首版范围、
可复用模块、需要补的能力和验收步骤，然后继续实现可运行的本地版本。
非关键未定项用合理默认值并记录；确实依赖我的账号或业务决策时再问我。

首次执行 pnpm install --frozen-lockfile 和 pnpm setup；保留已有锁文件。
不要覆盖已有 .dev.vars，不输出密钥、Cookie 或邮件验证链接。
保留登录、用户数据隔离、英文默认和 /zh 中文路由。
私有图片可按需启用并接入头像/项目封面，先读 docs/FILES.md；AI 和额度账本尚未实现，按需求单独开发。

完成后按改动范围运行检查，查看实际页面，交付本地地址、修改说明、
验收结果和待配置项。没有额外授权时，不提交、推送、部署、开通付费服务，
不发送真实邮件，不使用真实模型额度或启用正式支付。
```

你只需要补业务需求，不用再次设计登录、数据库或 UI 技术栈。例如：

```text
产品：Snippet Shelf，面向独立开发者的私人代码片段库。
首版：注册登录 → 新建片段（标题、语言、正文）→ 搜索 → 编辑/删除。
只允许用户访问自己的片段，保存后刷新仍在；中英文和手机都可用。
复用现有认证与工作台，将“项目”示例改为片段业务。
首版不做 AI、文件、团队协作或支付。请做完本地可验收版本。
```

这是任务示例，当前底座没有代码片段业务。

## Agent 首次启动与开发顺序

先检查工作目录、未提交改动、Node/pnpm 版本、已有配置和端口。保留其他工作，不为启动新项目停止其他服务。当前开发和开发 E2E 固定使用 3100；若已占用，先确认是否为本项目。多个产品可错峰运行；改端口时要一起调整 origin、脚本和测试配置，详见 [开发手册](DEVELOPMENT.md)。

```bash
pnpm install --frozen-lockfile
pnpm setup
pnpm dev
```

建议 Node.js 24、pnpm 12.11.2。`setup` 生成独立本地密钥和本地 D1，已有 `.dev.vars` 不会被覆盖。英文地址是 `http://127.0.0.1:3100`，中文地址是 `http://127.0.0.1:3100/zh`。

本地注册后从 `/dev/inbox` 或 `/zh/dev/inbox` 打开验证链接，再登录。无需真实邮箱供应商。收件箱包含敏感验证链接，只用于匹配 origin 的本机开发，不要通过公网隧道展示。没有预设管理员、共享账号或默认密码。

Agent 按下面顺序开发并记录必要决定：

1. **核对能力**：区分已有底座、需要开发的业务、需要外部账号的功能；不把配置占位当成可用服务。
2. **形成首版**：把用户流程、数据归属、页面和验收标准写入 `PROJECT.md`，不先搭插件平台或重建底层框架。
3. **替换品牌与示例**：调整名称、双语文案、图标和工作台。明确是否保留、扩展或替换示例项目模块，不盲目全局替换所有 `starter` 字符串。
   界面开发前在 `PROJECT.md` 写明视觉方向、信息密度、主要操作与页面组合依据；无参考时从产品场景推导。按需读取 `docs/FRONTEND.md` 和 `/dev/ui` 样板，复用组件与组合源码；当前绿色工作台是示例，新产品可以更换品牌和排版。
4. **实现业务**：复用认证、服务端验证与 UI；每个私有读写按当前用户限定。新增 schema 用 `pnpm db:generate` 生成新迁移，再执行本地 `pnpm db:migrate`。
5. **验证并交付**：完成下面的检查，记录真实结果和限制，更新产品 README、变更记录及 `PROJECT.md`。

不要手改 `src/routeTree.gen.ts`、`worker-configuration.d.ts` 或已经应用的 SQL 迁移。保持底座来源版本记录；产品自己的版本可以另行演进，不把业务版本冒充新的上游底座版本。

## 需求应该落到哪里

| 需求                         | 优先查看或修改                                              | 约定                                            |
| ---------------------------- | ----------------------------------------------------------- | ----------------------------------------------- |
| 产品名称、描述、套餐项目上限 | `src/config/site.ts`                                        | 文案与服务端限制同步                            |
| 首页、套餐与工作台页面       | `src/routes`                                                | 复用文件路由和受保护 `/app`                     |
| 主题、图标、表单组件         | `src/styles.css`、`public/favicon.svg`、`src/components/ui` | 复用 tokens、Base UI、Lucide                    |
| 中英文文案                   | `src/i18n/en.json`、`zh.json`                               | 两份字典同步，运行 `pnpm locale:check`          |
| 新业务模块                   | `src/modules`、`src/server/api.server.ts`                   | 复用请求校验、授权和业务限流                    |
| 数据模型                     | `src/db/schema.ts`、`migrations`                            | Drizzle 生成新迁移，私有数据关联用户            |
| 邮箱与 Google 登录           | `src/modules/auth`、`src/modules/mail`                      | 按请求构建认证，未配置时诚实提示                |
| 支付                         | `src/modules/billing`                                       | Stripe / Creem TEST，验签并读取当前状态决定权益 |
| 云资源与环境                 | `wrangler.jsonc`、本地私有配置                              | staging/production 独立，秘密不用 JSON vars     |

示例项目的 Free 3 / Pro 50 限额、项目状态和列表上限都是示例业务规则。换成新业务时需要重新定义并发配额和权限，不能仅改页面文字；不要为了测试通过关闭服务端配额或认证。

## 后续继续开发的任务模板

需要采用底座更新时，直接说 `$aster-new 检查当前底座更新，接入适合本项目的改进并完成回归`。Agent 先扫描来源版本、内容指纹与产品差异，再按模块合并、回归、记录采用路径；旧产品无基线时保守审查，不重新初始化。新产品提供 `project:upgrade`，旧产品可直接运行源目录脚本。备份、回退、部分升级及证据范围见 [升级指南](UPGRADING.md)。

在已有产品内加功能时：

```text
继续当前项目，先读 AGENTS.md、PROJECT.md、starter.project.json 和相关源码。
执行 project:doctor 与 project:status；若初始化中断，执行 project:resume，保留现有改动。
本次需求：[描述用户要完成的事情]
涉及用户与数据：[谁能看、谁能改、哪些数据私有]
验收标准：[操作步骤、成功/失败/空态、刷新后应保留什么]
本次不做：[范围外事项]
复用现有模块完成实现、相关检查和浏览器验收，更新文档与 PROJECT.md。
若涉及外部配置，先检查已有连接、权限与本次授权；在允许范围继续配置和真实验收。
确实需要我处理登录验证、平台审核或缺少权限时，只说明当前阻塞和最小操作，补齐后继续。
```

准备预发布时：

```text
请读取 docs/DEPLOYMENT.md，并按当前实际配置准备 staging 发布方案。
先读 docs/COSTS.md，默认免费优先，初期新增云服务费用目标 USD 0/月。
分别列出 Workers/D1、事务邮件、文件和 AI 的需要、限制、实现状态与费用，
不要因为 CF 发信要求 Paid 就直接将整个项目设为付费方案。
核对独立 Worker/D1、域名、邮件、Google、所选支付渠道的测试配置和数据迁移。
先完成本地生产构建验收、配置检查、迁移与恢复步骤、待我填写的配置清单。
不要输出秘密。只做准备与检查，暂不创建云资源、远端迁移或部署。
交付可审阅的配置差异、执行命令、可能费用和远端验收步骤。
```

准备完成后，你再明确授权目标环境及实际执行范围。云端操作遵循 [部署手册](DEPLOYMENT.md)，不能把本地测试通过写成已上线。

新项目会在 `starter.project.json.decisions` 记录 `cloud-cost-policy`，并填入 `PROJECT.md`；`project:status` 展示成本偏好，`project:doctor` 只检查记录存在，不读取实际账单。已有产品缺项时按当前用户意图增量补齐。预算记录不是购买授权；不把 Skill 调用等同于同意开通 Paid、绑卡或自动超额计费。

认证默认称呼/邮箱/密码，Google 为可选。选择发生在需求阶段，配置与真实验收发生在 staging，production 发布前检查所选能力。未选的 Google 不在访客页面展示；邮件未配时注册与找回入口暂不开放。正式发布按选择要求 `auth-email-live` 和/或 `auth-google-live`；无账号展示站不要求这两项 的真实 provider 记录和证据。`deploy:check` 不读远端；实际 deploy 在构建前只读检查必需 secret 名称。完整规则和验证范围见 [认证发布时序](DEPLOYMENT.md#认证选择与发布时序)。

邮件优先沿用用户指定或已接通服务；无既有选择时，确认目标账户已有 Workers Paid 且 CF 发信适用则默认优先 CF，否则按用户偏好和现有环境选择 Brevo 或 Resend。`MAIL_MODE` 明确指定一家；在 `mail-provider` 决策记录选择依据，不因某家适配已存在就默认开通付费服务。API key、域名/激活以及旧产品差异合并见 [邮件指南](MAIL.md)。用户 Skill 链接可定位当前底座源；已有产品复制的旧 Skill 不会自动更新，先比较版本和实现，保留原有 Google、页面、数据与密钥。

用户要求真实接通时，配置和验收由 Agent 继续推进，默认本地首版的示例不应缩小该目标。需要真实接入邮件时可直接使用：

```text
$aster-new 在当前项目接通邮箱注册和密码找回，并完成真实收信验收。
按当前底座的邮件指南增量合并，保留现有 Google、页面、数据和密钥。
允许在本项目指定的 staging、现有邮件账户及发信子域内配置和发布验收版本，
使用我授权的自有测试邮箱完成实测；保持免费优先，不开通付费套餐，不发布 production。
能执行的配置和验收由你完成；缺少账号登录、人工验证、审核或权限时只告诉我具体哪一步。
```

账号、域名和测试邮箱优先读取项目上下文；缺少必要目标时再确认。该示例授权限于写明的环境和用途，不授权向业务用户发测试邮件或擅自联系供应商支持。若用户明确“只列步骤、暂不部署”，应遵守；需要部署新代码才能验收时，请求该项具体授权，不能悄悄将“暂不部署”解释为允许 staging 部署。[执行与接力规则](MAIL.md#agent-执行与人工接力)。

外部配置任务用 `pnpm project:service status` 读取账号、域名、凭据、部署、投递和认证阶段；Agent 在授权内执行后记录，遇到具体人工阻塞才接力。目标与证据指纹用于恢复和识别过期状态，不代替远端核验或业务验收。格式、命令与旧项目接入见 [断点续做](SERVICE-WORKFLOW.md)。

## 什么算交付完成

应用代码改动至少运行：

```bash
pnpm check
pnpm format:check
```

`check` 在机器计划存在时先校验记录，再检查语言字典、构建、lint、类型和单元/集成测试。它允许尚未完成的业务计划；结束交付前另用 `project:check --ready` 检查必需用例。另按改动选择：

| 改动                            | 补充验证                                                          |
| ------------------------------- | ----------------------------------------------------------------- |
| 用户流程、登录、业务 API 或界面 | `pnpm exec playwright install chromium`（首次）及 `pnpm test:e2e` |
| 运行时、认证或环境配置          | `pnpm test:production`                                            |
| 界面                            | 查看实际桌面/手机、深浅主题、加载/空/错误状态和交互               |
| 纯文档                          | 格式、相对链接及命令/路径与源码一致性；不必重复应用全量测试       |

测试前确认环境仍为本地测试配置。开发 E2E 会向本地开发 D1 写入 fixture 用户；生产构建测试使用隔离临时库与假凭据，临时占用 HTTPS 3110。相关构建/测试串行执行；期间不同时编辑源码触发热更新。不要停掉不属于此次任务的端口进程。

Agent 最终应该交付：

- 可打开的本地地址与最短操作路径；若服务没启动，应说明启动命令。
- 本次实现与未实现范围，核心改动路径。
- 实际执行的命令及结果、浏览器交互和截图证据；没有执行就标明原因。
- 待填写配置与真实供应商待验收步骤；秘密只填写私有配置或供应商控制台。
- 数据模型/迁移说明，以及下一次继续所需的 `PROJECT.md` 状态。

## 当前底座能直接复用到什么程度

账号管理复用 [账号安全设置](ACCOUNT-SECURITY.md)：既有设置页支持按实际凭据改密、设备摘要及撤销其他会话；只返回非凭据会话 ID，改密轮换 Cookie，不把 SDK 原生 token JSON 返回客户端。旧产品应合并完整鉴权/API/UI/词典依赖并回归，原生 `authClient.listSessions/changePassword/revokeSession` HTTP 调用需迁移到私有接口，不能只复制界面。

邮箱认证、本地开发邮件、私有 CRUD、工作台、双语/主题、项目限额、用户运营、最小操作记录和测试支付同步代码已经存在。Google 和 CF 邮件已接线，仍需新产品自己的账号配置和真实验收；Stripe / Creem 均只支持测试环境，按 PAYMENTS.md 分别验收。

个人数据导出与账号注销见 [账号生命周期](ACCOUNT-LIFECYCLE.md)：有支付历史时重新核对平台，核对通过后原子归档；未知/未解决账务仍拦截。新业务必须扩展所属数据的导出/清理范围。升级采用新增迁移、完整认证钩子、结账预留和归档回调处理；旧的未完成邮箱验证链接需重发。

**AI 调用、消费额度账本、真实支付与完整账务保留管理、团队组织及自动升级未实现。** 有这类需求时，应把它们作为新增业务任务，补授权、失败状态与验收。复制 Aster 不会自动获得真实登录供应商、发信资格或收款能力。

新产品后续更新底座时，先对照 `starter-version.json` 与底座 `CHANGELOG.md`，审阅差异和新迁移，保留产品改动，再回归。当前没有“一键无冲突升级”能力。

## 视觉主题与私有图片

使用 [主题指南](THEMES.md) 选择 Sage / Catalog，并记录 visual-theme 决策及产品 PROJECT.md；不因选商品风格自动接支付或登录。需要头像/项目封面时按 [图片指南](FILES.md) 选 files，先本地验证上传→刷新→引用→替换→删除和账号隔离，再按授权处理独立环境的 R2。不要把本地测试当作 files-live 云端证据。

## 轻量内容与网站素材

需要文章、帮助或公告时读 [内容管理](CONTENT.md)，选择 content 并先完成本地编辑→预览→发布→匿名读取→撤下。文字不强制选 R2；封面另选 files，用独立的站点素材接口，不能公开 private file_asset。保留 shared 归属、草稿/发布快照和版本冲突保护，扩展个人导出/注销时不误删站点资产。目标环境配置和 content-live 真实业务验收在授权内执行，本地结果不继承为云端证据。

## 运营后台

账号管理读 [ADMIN.md](ADMIN.md)：使用已验证、未停用的管理员登录 `/app/admin`。首次本地显式授予；停用/恢复按版本提交并撤销会话，保留数据及支付回调。自己、最后一位有效管理员与注销受保护。升级包括迁移、触发器、服务端状态检查、页面、CLI、日志脱敏及实际回归，不只复制页面。
