# 页面规划与可选组合

Aster 的页面蓝图帮助 Agent 将产品需求变成有内容的用户流程，不是另一套技术能力开关。先读产品已有 PROJECT.md、页面、品牌与组件；已有站点优先增量保留。没有参考时根据实际用户与操作推导，不例行要求用户先选模板。

## 从需求到页面

实现前在产品 PROJECT.md 的“界面与内容”记录以下决定；选择依据标明用户指定、已有上下文或本次推导，未知事实保持待确认。

1. **用户与结果**：谁在什么场景进入，最想完成什么，什么结果算成功。
2. **页面路径**：入口 → 浏览/输入 → 详情/结果 → 下一步。逐页写明主要操作，不能只列首页、后台、设置。
3. **内容结构**：每页需要解释的问题、区块顺序、内容密度、与下一页的关系。官网不强制完整堆叠所有营销区块；简单工具也不必先经过一整页营销文案。
4. **内容来源**：实际业务记录、用户材料、可核实公开来源、明确的虚构演示或待补材料。没有评价/客户/统计时省略对应区块，不生成假的背书、增长数字、支付状态或可用性承诺。
5. **视觉方向**：延续品牌或从场景推导字体层级、颜色、留白和布局。示例绿色、侧栏和虚构品牌都不是产品要求。共享控件的尺寸与键盘语义仍按 FRONTEND.md。
6. **状态和边界**：加载、空数据、失败重试、成功、长文本、权限与未配置服务的行为。明确哪些操作保存到服务端，哪些只是演示；保存必须以服务端结果为准。

在 starter.project.json 用现有 decisions 记录 `page-composition` 的选择/依据，tasks 记录实现路径，acceptance 记录当前产品自己的实际流程证据；无需增加运行时 feature。复制样例不继承验收通过声明。需求/实现变化时重置受影响记录。

## 四类可选蓝图

| 类型       | 适合的流程                  | 可复用结构                                                              | 样例中的交互                                          |
| ---------- | --------------------------- | ----------------------------------------------------------------------- | ----------------------------------------------------- |
| 产品官网   | 先理解产品，再体验/开始使用 | 首屏与产品示意、功能说明行、步骤、体验表单、FAQ、结尾操作               | 虚构 Fieldnote：说明 → 填写三个字段 → 检查简报        |
| 目录与阅读 | 先找内容，再深入阅读或贡献  | 搜索/分类、编辑式内容列表、完整详情、页内目录、相关条目、提交表单       | 虚构 Margin：搜索 → 阅读指南 → 相关样例；临时添加资源 |
| 商品目录   | 按图找商品，再查看详情      | 大图首屏、搜索、商品网格、详情与购买信息预览                            | 虚构 Ordinary Objects：搜索 → 详情；无真实订单        |
| 数据工作台 | 高频处理记录，直接开始工作  | 紧凑工具栏、实际记录派生的进度、主从表格/详情、分步创建、反馈与状态预览 | 虚构 Launchpad：筛选 → 编辑备注/状态 → 分步新建任务   |

一个产品可以组合：产品官网作为入口，数据工作台承载核心操作，目录/阅读用于帮助。页面组成不决定 auth/billing/AI/files 等技术能力：公开目录不必注册，普通数据工具不需要 AI，内容示例也不是已接通 CMS。

样例故意不预装营销追踪、CMS、图表库、动效库或外部图片。需要图表时先确定问题、数据和单位；有受控真实内容后再添加图片、视频或统计。不要为了丰富度同时引入多套控件或把每个区块都做成卡片。

## 预览与实现入口

启动本地服务后访问 `/dev/blueprints`，中文 `/zh/dev/blueprints`；也可从 `/dev/ui` 的“页面蓝图”进入。地址的 `kind=product|directory|workbench` 选择示例并支持刷新/语言切换；业务演示状态只保留在内存，刷新或离开该示例会重置。

| 入口                                           | 用途                                                           |
| ---------------------------------------------- | -------------------------------------------------------------- |
| `src/routes/dev/blueprints.tsx`                | 本地入口、样例选择与统一演示边界                               |
| `src/components/dev/blueprints/product.tsx`    | 完整官网与简报表单/结果                                        |
| `src/components/dev/blueprints/directory.tsx`  | 搜索、分类、阅读详情与临时贡献                                 |
| `src/components/dev/blueprints/workbench.tsx`  | 表格/详情、编辑、两步表单、加载/空/错误预览                    |
| `src/components/patterns/content-patterns.tsx` | ContentHeading、FeatureRows、ProcessSteps、FaqList，可独立复用 |
| `src/components/ui/progress.tsx`               | 共享进度显示，提供范围与当前值的可访问语义                     |
| `src/components/ui/disclosure.tsx`             | 原生 details/summary，支持 SSR 和键盘展开                      |

产品官网与商品目录复用 RevealGroup 展示首屏渐次入场，FeatureRows / ProcessSteps 首次滚动出现；数据工作台不增加入场等待。规范与降级验收见 [页面动效](FRONTEND.md#页面动效)。

样例不请求数据库、邮件、支付或模型，不保存账号记录。品牌和条目都是虚构；工作台进度只来自当前样例记录，不能作为产品运营数据。错误/加载由显式预览选项触发，不冒充真实网络失败。开发入口仅限 ENVIRONMENT=local 且匹配回环 origin；staging/production 均返回 404，两个语言都要检查，不加入公开导航或 sitemap。

## 用到实际产品时

先移植有用的结构与控件，再接实际页面路由、数据模型和私有 API，不要整段复制演示状态管理后宣称功能上线。

- 用真实领域对象替换虚构名称、字段和通用阅读文案。演示品牌不写入产品名称或 SEO。
- 列表数据增长后使用服务端搜索、分页与总数；浏览器内筛选只适用于完整、有界集合。
- 资料提交需补权限、校验、持久化、审核/公开范围与错误反馈；本地添加不等于已发布。
- 表单结果需明确是格式整理、计算还是外部生成；没有模型调用就不写 AI 已完成。
- 内容页可先用仓库中的受控文件，按需求再接 CMS；来源、更新时间、许可与可见性按实际内容维护。
- 外部能力按 MODULES.md 选择并分别验收，不为布局补上未选的服务按钮、绑定或费用。

验收当前产品的入口 → 主要操作 → 结果 → 刷新恢复、跨用户隔离（如适用）、失败恢复和未连接服务。检查中英文、深浅主题、手机、长文本、键盘焦点与 Disclosure/弹窗操作。样例的刷新重置只适用于开发演示，不能作为真实保存流程的标准。

## 商品目录与两套主题

`kind=shop` 提供原创插画、虚构商品/示例价格、搜索、详情、购买信息预览与 FAQ；刷新重置，不创建订单或调用支付。Catalog 采用中性图像目录风格，Sage 保留绿色工具风格，两者可在本地蓝图顶部比较，详见 [主题指南](THEMES.md)。参考站点仅用于理解视觉原则，不复制个人素材或把它当商品数据。
