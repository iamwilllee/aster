# 免费起步与按需升级

核验日期：2026-10-23。金额为美元；以下是官方公开额度快照，不代表已读取你的账户、已完成云端验收或获得购买授权。执行前重新核对官方价格与账户资格。

Aster 代码与 Skill 使用 MIT 许可，不单独收取软件许可费。执行 Agent 的订阅/API 费用、域名和云服务分别计算；安装 Skill 不会自动开通这些服务。

按 [能力选择](MODULES.md) 仅配置所选服务。公开展示站可直接验证页面与 Workers，无需 D1、认证或邮件；下面的数据和账号阶段只适用于有对应需求的产品。

## 默认递进顺序

1. **本地**：用本地 D1、测试收件箱和模拟供应商验证业务，不产生实际云服务调用。测试收件箱不能暴露到公网。
2. **免费云数据验证**：优先 Workers Free + D1，使用 workers.dev 或已有域名；只创建所需资源。预发布/生产隔离，但账户额度共用，不是每个 Worker 各有一份免费额度。
3. **登录与事务邮件**：分别确定登录方式、邮件供应商和容量，优先用户指定或已接通服务。无既有选择且目标账户已有适用的 Workers Paid 与 CF 发信资格时默认优先 CF；否则按偏好、现有环境、激活和容量选择 Brevo / Resend。CF 发信需要 Paid 不等于网站/D1 必须 Paid；两种外部适配均已实现。验证邮件、密码重置、会话、权限和真实收件均需验收，详见 [邮件指南](MAIL.md)。
4. **按证据升级**：出现真实容量或运行限制，或用户明确需要付费功能时，再列免费替代、固定费、按量项、用量估算和目标预算，按已有授权执行。

默认目标是初期**新增云服务费用 USD 0/月**，不是永久零成本承诺。已有 Paid 账户仍可能因新增用量产生费用；不要擅自降级账户，也不要把共享套餐固定费重复算成每个项目都要再付一份。

## 运行限制与真实验收

Workers Free 的 CPU 限制是独立约束。当前邮箱/密码认证使用 Better Auth 的密码哈希，SSR 和其他代码也消耗 CPU；**尚未证明当前完整认证在 Workers Free 上满足限制**。在目标云环境检查 CPU、错误日志与实际登录流程，不能用本地响应耗时替代云端 CPU 数据。

若超限，先识别和优化实际热点，比较保持安全强度的实现或用户接受的登录方式，再评估 Paid。不得为达成“免费”关闭邮箱验证、使用弱密码哈希、暴露验证链接或跳过私有数据授权。未配置邮件时可准备独立的数据/公开页面验证，但不宣称注册闭环已完成。

免费资源也需要迁移和恢复方案。只迁移用户明确需要的业务数据，不整库上传开发测试账户、会话、邮件验证/重置令牌或测试订阅。

## Agent 应记录什么

在 `PROJECT.md` 的外部服务部分记录：

- 当前阶段、目标账户的套餐与共享额度是否已核验；无法读取就写未知。
- 服务选择、免费限制、超限行为、是否需要绑卡或付费套餐、官方 URL 与核验日期。
- 预估用量与实际测量，包括 CPU、D1 扫描/写入、存储、邮件和模型调用；没有数据不编造成本。
- 免费路线可完成的流程、尚未接入的能力、真实云端/供应商待验收项与升级触发条件。

机器记录复用 `starter.project.json` 的 `decisions`，无需引入第二套云配置：

```json
{
  "id": "cloud-cost-policy",
  "question": "云服务成本策略",
  "status": "resolved",
  "value": "免费优先；初期新增云服务费用目标 USD 0/月；付费能力按实际需求单独评估",
  "basis": "default",
  "reason": "先验证免费档容量与运行限制；外部操作和付费授权仍以用户当前指令为准",
  "blocking": false
}
```

新产品初始化会生成此偏好；用户明确给出预算时改用 `basis=user` 并记录原意。`project:status` 展示该记录，`project:doctor` 只检查是否记录，不读取账单、不承诺零费用。旧计划不因缺少此项而失败；上云前由 Agent 增量补齐。

预算数字、`resolved` 状态和文件内容都不是购买凭据或用户授权。不要把“接入 CF”“数据上云”“使用已有套餐”理解成同意绑卡、开通新订阅、充值或开启自动超额计费。用户已有明确授权时沿用范围；用户要求先出方案则停在可审阅方案，不替用户操作账户。
